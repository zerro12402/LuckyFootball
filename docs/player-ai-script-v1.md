# 幸运足球球员 AI 脚本手册 · 接口 v1

## 先认识《幸运足球》

《幸运足球》是一款 6 对 6 的非正式足球观赛游戏。双方球员全程由 AI 控制，玩家可以观赛和下注。球员会跑位、带球、传球、射门和抢断，也能近身攻击；高速射门击中对手时，还有可能把人击倒。球队仍靠进球争取胜利。

球队的踢法会随局面变化：我方进攻时，球员会推进或找位置接应；对方进攻时，会回防、逼抢或尝试抢断；球变成无人控制的散球时，会争球或保护身后。前锋、中场、后卫和门将各有职责，所以并非每个人都会去追球。

**脚本决定球员想做什么，比赛规则决定能不能做、结果如何。** 球员需要重新选择行为时，游戏会根据球权、位置和动作状态给出当前可用的选择。脚本可以提高某个行为被选中的机会，也可以直接指定一项合法行为。比如，持球前锋受压时可以更偏向传球；到了门前、有合法射门机会时可以更愿意射门。提高射门权重只会让他更常选择射门，不会提高射门命中率。


## 快速开始

1. 在游戏中按 **F1**，然后从左上角模式菜单打开 **球员 AI 实验室**。
2. 从当前正式阵容中选一名蓝队前锋，填写比赛种子（0～2147483647）。
3. 粘贴或编辑完整 JSON，点 **校验脚本**。错误会显示 JSON 行号或规则位置。无效提交会保留已校验的脚本和当前比赛。
4. 点 **绑定并试跑**。只给选中的前锋启用脚本，其余球员使用内置 AI。底部显示种子或最近一次回退原因。
5. 点 **打开 AI 实验室**，选择 **同种子默认复跑**，用上次脚本试跑的种子和同一正式阵容重新开赛。

## 语法

顶层字段固定为 `version`、`rules`、`default`。从上到下检查 `rules`，采用第一条所有条件都满足的规则；没有匹配项则用 `default`。

每条规则含 `when` 和 `then`。条件写为 `["字段", "比较符", 值]`。数值可用 `== != < <= > >=`，布尔值与字符串仅支持 `== !=`。数字、布尔值及字符串使用 JSON 原生类型。

可返回三类对象：

- `{}` 走内置策略。
- `{"weights":{"pass":2}}` 将传球类别当前权重乘以 2，其他类别保持原权重。倍率为有限非负数，0 表示本次排除该类别。仅调整当前存在的类别，权重不能全部变成 0。游戏先抽类别、再抽目标。
- `{"behavior":"pass","target":"first"}` 直接选择合法类别及目标。移动、射门和保持站位用空串作为目标。传球和抢断使用当前合法的球员 ID，或用 `"first"` 取按稳定 ID 排序的首个合法目标。直接选择不消耗类别和目标抽签。

## 可用于条件的局面字段

| 字段 | 类型和单位 |
| --- | --- |
| `self.id` | 字符串，本人球员 ID |
| `self.x`、`self.y` | 数字，米，以球场中心为原点；X 正向统一朝对方球门，Y 正向朝画面下方 |
| `self.goal_distance_m` | 数字，到对方球门中心的直线距离，米 |
| `self.owns_ball`、`self.pressured` | 布尔值，是否持球、是否处于 AI 受压状态 |
| `ball.x`、`ball.y`、`ball.height_m` | 数字，球的平面坐标与离地高度，米 |
| `ball.vx`、`ball.vy` | 数字，球速分量，米/秒，坐标朝向同上 |
| `ball.owner_id` | 字符串，持球者 ID；无主球为空串 |
| `phase` | 字符串，`attack`、`defend` 或 `loose` |
| `teammate_count`、`opponent_count` | 数字，场上队友（不含自己）和对手人数 |
| `nearest_teammate_m`、`nearest_opponent_m` | 数字，最近队友和对手的平面距离，米；没有该类球员时为 -1 |
| `has.<行为>` | 布尔值，例如 `has.shoot` 表示当前候选中存在有权重且目标合法的射门 |

## 行为与目标

| 行为 | 何时出现 | 目标 |
| --- | --- | --- |
| `dribble` | 前锋持球，可带球推进 | 空串 |
| `pass` | 持球且有合法队友 | 队友 ID 或 `first` |
| `shoot` | 持球且符合 AI 射门范围 | 空串 |
| `support` | 当前职责允许接应 | 空串 |
| `run_forward` | 接应目标处于本队进攻方向的前方 | 空串 |
| `press` | 当前承担主逼抢 | 空串 |
| `tackle` | 有合法抢断机会 | 对方持球者 ID 或 `first` |
| `chase` | 当前承担自由球争抢 | 空串 |
| `hold` | 当前允许保持站位 | 空串 |
| `return` | 当前需要回防或回位 | 空串 |

`support` 与 `run_forward` 共用宿主接应计划，不能在同一个结果里同时加权。脚本只在游戏需要重选行为时运行。动作的实际接受、对抗、进球等仍由游戏裁定。脚本没有文件、网络、时钟、Godot 对象、循环、跨决策记忆或比赛写入能力。球员起跳、空中终结、争顶和攻击由游戏的原有逻辑管理。

源码上限 8192 UTF-8 字节，JSON 最深 8 层，最多 24 条规则，每条 1～8 个条件，单次最多执行 128 次比较，目标 ID 最长 64 字符。运行错误、超限和当前非法结果会在本次决策使用内置 AI，并显示原因。

## 可运行示例

受压时提高传球倾向，接近球门时提高射门倾向。其余情况下使用默认策略。

```json
{
  "version": 1,
  "rules": [
    {
      "when": [["self.owns_ball", "==", true], ["self.pressured", "==", true], ["has.pass", "==", true]],
      "then": {"weights": {"pass": 2}}
    },
    {
      "when": [["self.goal_distance_m", "<", 8], ["has.shoot", "==", true]],
      "then": {"weights": {"shoot": 2}}
    }
  ],
  "default": {}
}
```

无球时，有向前的接应机会便直接前插；否则按原有策略。

```json
{
  "version": 1,
  "rules": [
    {
      "when": [["self.owns_ball", "==", false], ["has.run_forward", "==", true]],
      "then": {"behavior": "run_forward", "target": ""}
    }
  ],
  "default": {}
}
```
