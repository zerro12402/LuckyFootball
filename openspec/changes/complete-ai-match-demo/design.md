# Design

## Context

参见 [proposal.md](proposal.md)。现有 MatchSimulation、GameLoop 和 BallRuntimeSystem 提供固定步与基础球路，测试输入和 TackleChaseAI 通过统一命令驱动。起跳/空中射门与争顶/头球任务已完成，足球击倒文档已同步，后续实现状态见 tasks.md。formal_match.tscn 仍为空入口，但不属于本变更拆分后的实现范围。

Notion《程序架构》《模块接口》用于核对全局边界；策划写《球员基本行为2》等专题页，功能程序设计写《程序架构》下独立子页。默认不做截图、录屏或离屏渲染。

## Goals / Non-Goals

**Goals:** 让空中动作、足球击倒、门将扑救及其接触顺序在共用测试模式与无场景测试中独立成立，为后续属性和正式比赛提供可复用规则。

**Non-Goals:** 本变更不实现全量属性绑定、体力曲线、正式阵容/场景与终场接口、完整球员 AI 或词条权重；这些需求已迁出。Demo 仍不制作门将主动接高空传球、头球传球、犯规或永久受伤。

## Decisions

### 1. 动作来源与规则分离

输入、测试预设及未来 AI 都提交 MatchAction，由模拟层复核资格并提交结果。单项规则接受显式数值上下文，不等待全量 CSV 属性接线或十二人装配；高层功能不得复制另一套动作规则。

### 2. 高度与球权保持连续

跳跃相位、高度与固定步计时作为球员状态，与射门动作正交。地面抢断在实际接触时核对高度；空中射门从当前球高一次性释放球权。高空争顶按连续球路、位置和到达时机选候选，近同时按已配置强壮度/技巧判定，头球直接改变轨迹而不临时取得球权。

### 3. 接触顺序与可替换判定

同一步内球员、门将与边界候选按首次接触时间和稳定 ID 排序；球路变化后重算余下时间。几何接触、闪避、击倒与球路响应分别返回结果，MatchSimulation 统一提交；规则核心不依赖节点。

F08 只比较离脚锁定射门基础值与目标强壮度，严格大于才倒；击倒后从比赛随机源抽一次 50%/50% 球路，未倒必反弹。高速阈值与反弹参数由配置提供。常规属性公式的全量接线归独立属性特性，保留本例外。

### 4. 门将规则接受命令输入

门将站位与合法扑救窗口可用测试动作驱动；射门/守门与站位等修正形成扑救判定，成功后输出抱球或扑出。抱球取得唯一球权，扑出继续自由运动并可补射。完整门将决策在 add-player-ai 接入，不能让本组依赖全 AI。

### 5. 共用测试模式

GameModes 选择入口与共用 GameBootstrap 装配各动作预设，支持重置和固定种子；沿用已有模式资源，不为各模块另建 .tscn。正确性由无场景规则、事件/快照和非渲染交互检查验证。正式场景资源隔离检查归正式比赛基础。

## Risks / Trade-offs

- **现有边界结算早于部分接触** → 统一接触时间，覆盖先撞人/先越线及球路改变后的余步。
- **概率击倒旧基线与临时规则冲突** → 策划、属性和公式页已按 3.1 同步；大于/相等及固定抽样回归锁定。
- **高层功能提前成为动作测试依赖** → 显式上下文和命令验证前四组，高层功能通过后续特性接线。
- **已有实现进度被拆分覆盖** → 原 1.1～4.4 保持编号与完成状态，迁出任务不伪装成已完成。

## Migration Plan

先完成本变更的动作/球路/扑救与跨动作验收，再依次接入以下特性：

| 顺序 | 特性 | 负责边界 |
| --- | --- | --- |
| 1 | [integrate-player-attributes-and-contests](../integrate-player-attributes-and-contests/design.md) | 真实七属性、体力与集中判定接线 |
| 2 | [add-formal-match-foundation](../add-formal-match-foundation/design.md) | 阵容、正式装配、计时与只读结果 |
| 3 | [add-player-ai](../add-player-ai/design.md) | 全部球员/门将决策及无词条整场运行 |
| 4 | [add-player-traits](../add-player-traits/design.md) | 词条定义、权重、正式/Demo 覆盖 |

旧 autonomous-match 规格中的阵容/计时/输出、AI、属性/体力需求分别迁入对应新规格，词条得到独立规格。原 8.1 保留为本变更 5.1；原 8.2 的核心检查保留为 5.2，正式入口检查迁至正式基础，完整整场检查迁至 AI/词条。下注挑战消费新正式比赛接口，词条随机生成与五场存档仍由挑战拥有。任何后续接入回退均不要求移除本变更的基础动作。
