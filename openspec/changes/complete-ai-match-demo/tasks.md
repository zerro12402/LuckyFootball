# Tasks

## 1. 起跳与空中射门

- [x] 1.1 在 Notion《球员基本行为2 — 多人交互行为》下保存带球起跳与空中射门策划设计，并在《程序架构》下建立对应程序设计子页；验证与低空接球规则不冲突、页面层级正确且职责与输入输出清楚。
- [x] 1.2 实现起跳、腾空、落地状态及球员/足球高度跟随；用起跳前、有效腾空、落地后的抢断资格测试验证。
- [x] 1.3 实现空中射门从当前高度一次性释放球权；用成功触球、触球前失球/倒地、空中球路的无场景测试验证。
- [x] 1.4 将已加入的带球起跳与空中射门测试功能并入现有共用 `GameBootstrap` 测试模式及 `GameModes` 选择入口，提供地面抢断、有效腾空、落地和空中射门预设与重置；清理独立测试场景及其引用，用场景引用/脚本解析检查和非渲染的动作事件、球权与高度断言验证。

## 2. 高空争顶与头球

- [x] 2.1 在 Notion《球员基本行为2 — 多人交互行为》补充高空球争顶、头球攻门/解围的策划规则，在《对抗判定公式》登记可调数值，并于《程序架构》下建立程序设计子页；验证文档明确先看站位与时机、再处理近同时对抗。
- [x] 2.2 实现连续球路的高空接触候选与同一步稳定排序，不复用普通低空接球；用单人先到、双方近同时和跨步球路测试验证。
- [x] 2.3 实现胜者直接头球攻门或解围而不临时控球；用两种结果、无头球传球和唯一球权测试验证。
- [x] 2.4 在现有共用 `GameBootstrap` 测试模式与 `GameModes` 选择入口中加入高空争顶/头球预设，覆盖单人先到、双方近同时、攻门、解围与重置，不新建独立测试场景；用模式切换、脚本解析和非渲染的争顶事件、球路与唯一球权断言验证。

## 3. 足球击倒与球路

- [x] 3.1 在 Notion《球员基本行为2 — 多人交互行为》修订足球击倒的策划规则，同步《球员属性》《对抗判定公式》的临时数值规则，并于《程序架构》下建立程序设计子页；验证旧概率基线与本规则的适用范围已明确。
- [x] 3.2 实现固定步内按首次接触时间排序的队员、门将和边界候选；用“先击中队员后到球门”和“先越线后接触”测试验证。
- [x] 3.3 将足球接触、闪避、击倒与球路响应拆为独立结果，按射门值大于或等于强壮度击倒，相等时固定反弹、严格大于时 50%/50% 继续/反弹；用相等值、低速接触、固定随机源、重复接触和连撞测试验证。
- [x] 3.4 在现有共用 `GameBootstrap` 测试模式与 `GameModes` 选择入口中加入足球击倒预设，覆盖射门穿过防守队员、未击倒反弹、击倒后继续/反弹及固定种子重放，不新建独立测试场景；用模式切换、脚本解析和非渲染的接触、击倒、球路事件顺序断言验证。

## 4. 门将扑救

- [x] 4.1 在 Notion《球员基本行为2 — 多人交互行为》第5.4节补充射门上中下三点、上/下扑、接触时50%成功抱球及失败漏球/中路击飞规则；在《程序架构》下建立《门将扑救与射门三点 — 程序设计》，同步《对抗判定公式》F04/F10、《球员属性》和动作表12/13行计划，明确旧扑出方案停用及未来属性算法替换；回读验证父子层级、唯一球权、手部锚点与禁接高空传球范围一致。
- [x] 4.2 实现普通/空中/头球射门实际释放时等概率锁定球门上中下三点，及统一命令驱动的门将上扑/下扑/正面接球窗口；在合法连续接触时仅抽一次50%成功，按射门序列去重并防止普通捡球绕过；用固定选点、0.49/0.50、接触前不抽数、三类来源、倒地/高空传球排除及接触/边界先后测试验证。
- [x] 4.3 实现成功原子抱球与逻辑手部持球点，上/下扑动画12/13行逐帧双手锚点及左右镜像，播完保持手持；失败上下扑播完且球穿过，中路失败第10行hit并击飞/倒地，球继续原轨迹；用三路成功/失败、唯一球权、不反弹/不额外减速、余步进球一次、暂停重置与固定种子测试验证，不制作旧扑出分支。
- [x] 4.4 在现有共用 `GameBootstrap` 测试模式与 `GameModes` 选择入口中加入门将扑救预设，提供固定通道及成功/失败注入，覆盖普通/空中/头球射门、上下手持、中路抱球/击飞、漏球进球、门将倒地与重置，不新建独立测试场景；用模式切换、脚本解析和非渲染的手部锚点、扑救事件、比分与球权断言验证。

## 5. 动作与对抗集成验收

- [ ] 5.1 运行确定性无场景联动测试，覆盖带球起跳→空中射门→扑救、传中→争顶→头球、射门→击倒→继续/反弹→进球或出界；验证同配置/命令/种子产生相同事件序列，并覆盖射门三点→三路扑救成功抱球或失败穿过/中路击飞→实际进球或出界。
- [ ] 5.2 检查共用测试模式的脚本解析和新增警告，并验证事件/快照读取不改变模拟或随机源；按项目约束不运行截图、录屏或离屏渲染测试。正式入口引用检查迁至正式比赛基础特性。
