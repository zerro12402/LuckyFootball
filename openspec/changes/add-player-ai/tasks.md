# Tasks

前置：正式整场集成依赖 `add-formal-match-foundation` 与 `integrate-player-attributes-and-contests`；单项决策可先用快照夹具。本清单迁入原 7.1、7.3 和 7.2 中的状态动作限制。

## 1. AI 契约与候选

- [ ] 1.1 在 Notion 专题设计页和《程序架构》程序设计子页补齐持球、无球、攻防与门将决策；验证候选、状态限制、随机源和动作提交边界清楚。
- [ ] 1.2 建立快照驱动的候选、合法性过滤、基础评分和统一动作输出；用无球、持球、倒地、冷却和输入快照不被修改的测试验证。
- [ ] 1.3 实现中性行为权重修正接口与合法回退，保留后续词条接入点；用恒等修正、零权重和非法动作不能复活的测试验证。

## 2. 足球与对抗决策

- [ ] 2.1 实现持球推进、传球、射门、带球起跳/空中射门及无球接应的候选选择；用固定位置/球权/高度快照验证行为窗口与目标合理。
- [ ] 2.2 实现回防、抢断、近身攻击和高空争顶/头球的选择，并让状态与体力影响候选和行为权重；用攻守转换、倒地恢复和动作失效快照测试验证。
- [ ] 2.3 将前置门将站位和扑救规则接入门将 AI，并处理抱球后的合法出球；用三类射门、扑出补射、倒地和高空传球不触发扑救测试验证。

## 3. 正式全 AI 集成

- [ ] 3.1 将双方十二人的动作来源接入正式装配与固定步循环，统一稳定球员/候选顺序及 AI 随机源；用同种子动作序列和非法提交无副作用测试验证。
- [ ] 3.2 在中性词条权重下完成十二人整场自主比赛，覆盖传射、攻守转换、倒地恢复和门将处理；验证无人操控仍到达唯一终场、球权唯一且重复重放一致。
