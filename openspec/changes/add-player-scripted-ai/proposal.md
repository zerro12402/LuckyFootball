# Proposal

## Why

在已实现的一名前锋脚本试跑基础上，让玩家为蓝队提交一份脚本，供前锋、中场、后卫和门将使用。脚本按当前球员的位置和局面选择行为。玩家还应能在游戏内用自然语言生成只影响局部局面的覆盖补丁，而不必在外部生成整份脚本再复制进来。

## What Changes

- 复用 v1 已实现的本地脚本编辑、静态校验、绑定和固定种子试跑。
- 脚本提交时解析为内部表示，比赛决策时通过受限 API 执行；不转译为 GDScript。
- 支持调整合法行为权重或直接选择合法行为及目标；失败回退内置 AI 并显示原因。
- 发布与接口版本匹配的可下载 Markdown 手册，提供示例和给生成式 AI 的提示词。
- 本次扩展以蓝队（home）为绑定单位，提交一次即可覆盖其前锋、中场、后卫和门将；不提供主客队选择，红队（away）始终使用内置 AI。各球员独立调用脚本。扩展位置条件、行为和目标，原单前锋 v1 试跑继续兼容。
- 门将可离开门线，但候选与目标限制在本方禁区。脚本不一次返回全队命令；赛后 Markdown／JSONL 导出、逐帧日志及联网投稿仍不在范围内。
- 新增版本化覆盖补丁：按作用域与条件局部调整合法候选，未命中继续使用内置 AI。
- 新增游戏内自然语言生成：玩家用一句话描述战术，经自填 DeepSeek Key 生成补丁或整份脚本，默认补丁；校验后绑定，失败不覆盖已有绑定。
- Key 仅保存在本机；生成请求只发送公开手册、战术描述与公开规则；脚本执行本身不联网。

## Capabilities

### New Capabilities

- `player-scripted-ai`：玩家脚本与覆盖补丁的提交、校验、执行、游戏内自然语言生成及公开使用说明。

### Modified Capabilities

无。既有比赛规则、内置 AI 默认行为和比赛阶段权限继续适用。

规划涉及球员决策策略、脚本运行与校验、只读公开接口、本地试跑入口、覆盖补丁、DeepSeek 请求与本地 Key 存储。详见 [玩家自定义 AI 策划](https://app.notion.com/p/411f67bb9cfa81f8a5a8c2762441362f)、[程序设计](https://app.notion.com/p/411f67bb9cfa818684aec198faf6f760)、[自然语言生成策划](https://app.notion.com/p/412f67bb9cfa81eb98c0ce209d4bdf81) 与 [程序设计](https://app.notion.com/p/412f67bb9cfa81c08118ea080cc3fe42)。
