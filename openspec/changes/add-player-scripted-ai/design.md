# Design

## Context

[玩家自定义 AI 策划](https://app.notion.com/p/411f67bb9cfa81f8a5a8c2762441362f) 与 [程序设计](https://app.notion.com/p/411f67bb9cfa818684aec198faf6f760) 为维护入口。现有 MatchPlayerAISource 调用 PlayerAI.choose，AIWeightModifier 只提供倍率，不能直接指定目标。覆盖补丁与游戏内自然语言生成见 [自然语言生成策划](https://app.notion.com/p/412f67bb9cfa81eb98c0ce209d4bdf81) 与 [程序设计](https://app.notion.com/p/412f67bb9cfa81c08118ea080cc3fe42)。

## Goals / Non-Goals

v1 已支持一名前锋试跑；本次扩展将一份脚本绑定给蓝队（home），供其前锋、中场、后卫和门将共享；不提供主客队选择，红队（away）始终使用内置 AI。仅提供即时诊断，不做赛后日志导出、集中生成全队命令、联网执行脚本或 GDScript 转译；自然语言生成只发生在比赛外的实验室，执行仍走本地已编译脚本。

## Decisions

1. 在既有选择点加入策略接口。宿主生成合法候选，策略返回权重调整或行为与目标；继续由现有计划推进和模拟裁定。第一步用测试策略验证接入。
2. 提交时解析、校验版本与静态引用，缓存内部表示；比赛开始锁定脚本和接口版本。只在现有决策时机运行，固定步继续推进动作。暂停、重置与重复调用沿用现有调度约束。
3. 公共 API 提供版本化值数据，坐标按本队进攻方向统一；不暴露内部快照或对象引用。用受限解释器和明确白名单，限制源码、指令和内存。首版无跨决策脚本记忆。
4. 运行时校验动态候选与目标；拒绝非法返回、负数和非有限权重。异常只回退本次决策；记录基础诊断。随机抽样仍由游戏管理，与对抗随机流隔离。
5. 公开手册与校验器共用接口定义，示例纳入测试。首版行为和目标清单见 Notion；手册只描述实际开放的接口。

## 多位置扩展（v2 已实现）

多位置扩展保留 v1 的 JSON 语义和限制，引入显式版本的扩展契约。实验室固定为蓝队（home）绑定，提交时只编译一次；开赛锁定蓝队绑定和脚本版本，其全队共享只读编译结果。每次调用只读取当前球员的角色、局面和候选，返回该球员的选择；随机进度、执行预算、行为计划和回退按球员隔离。无效提交保留上一个有效脚本。默认复跑沿用同阵容、配置及种子，关闭蓝队脚本；红队始终使用内置 AI。

扩展条件涵盖自身角色、球队进攻／防守／自由球状态、本人／队友／对手／无人持球、当前职责、球的高度及来源，以及指定行为是否存在合法目标。字段、类型、单位、缺省值与枚举由公开契约统一定义。脚本只能选当前合法候选；角色影响可见候选与权重，不直接决定动作结果。

共同候选含保持、带球、传球、射门、接应、前插、逼抢、抢断、追球；中场补充回撤接应、封线及中路支援，后卫补充回位、保护球门、盯防和后场接应。扩展还纳入现有规则支持的带球起跳、空中射门及近身攻击；复用既有计划与固定步窗口。当前版本没有头球，候选不包含头球攻门或解围。需要新增行为标识时，先明确到现有动作或计划的映射；不把封线当作必定拦截，不开放指定球员为射门目标。

门将分支仅开放合法的站位、横移、扑救准备及持球后原地传球；仍由既有固定步窗口执行扑救。门将可离开门线，但候选与校验共同保证不追出本方禁区、不出击到禁区外。没有匹配角色规则时可用脚本默认分支委托内置 AI。

脚本球队的外场球员在防守且对方持球时，可获得一个 opt-in 的 press 候选，即使不是主防球员；默认权重为零，只有脚本显式加权才会生效。内置 AI 的候选生成与主防分工保持不变。

版本化手册提供一份覆盖四位置的可校验脚本及一次绑定流程；v2 手册位于项目的 `docs/player-ai-script-v2.md`，由实验室提供复制入口。v1 手册独立保留。

## 覆盖补丁与自然语言生成（已实现）

覆盖补丁使用显式版本（v3）描述作用域与条件，只调整作用域内当前合法候选的权重或指定合法选择。所有命中条件全部生效，同一行为倍率相乘；未命中的决策保持内置 AI。单个条件引用不可用行为时只丢弃该项，合并不因一项失效而整体回退；合并后无正权重时按既有路径回退内置并记录诊断。v1／v2 语义不变，补丁不新增候选或行为。

自然语言生成默认产出覆盖补丁，仅在玩家明确要求重写整队时才产出整份脚本。生成器是不依赖场景树的纯逻辑，网络传输以可注入接口提供；提示词包含公开手册、补丁规范与玩家描述，不发送比赛状态。模型输出必须通过正式编译器才能绑定，失败携带错误有限修复，仍失败则保留已有绑定。Key 只保存在本机，不进入日志或导出；生成在比赛外单飞执行，可取消，不进入固定步循环。

生成成功后把玩家输入、生成 JSON 与时间写入本机历史（最多 20 条，重复内容合并到最新）。选择历史只恢复输入与已编译脚本，不再次请求模型；历史不参与比赛状态，也不随导出或提交分发。

叠加采用本地确定性合并：解析当前与新生成的两份 v3 文档，把各自 scope 转成每条规则的前置条件，再拼接 modifiers；同行为倍率在运行时相乘。合并结果重新编译后替换当前脚本；当前脚本不是 v3、单条条件超过 8 个或规则超过 24 条时保持原脚本并提示。默认开启，可关闭改为整份替换。

## Risks / Trade-offs

- 只提供倍率无法表达直接选目标；策略接口同时支持两种返回形式。
- 公开内部类型会使实现变动破坏玩家脚本；使用稳定、可版本化的值数据。
- 脚本执行失败不得卡住固定步；按预算中止并回退。赛后报告与 JSONL 待另立变更，不把完整日志当作首版依赖。
- 模型输出不稳定且不可复现；以保存的已编译补丁为复现依据，不把重新生成视为等价。
- 客户端保存 Key 存在被本机读取的风险；首版明确告知，代理模式另立变更。

## Migration Plan

先验证默认策略等价，再接入受限运行器与本地试跑入口；不绑定脚本时维持既有比赛。覆盖补丁与生成入口在 v1／v2 路径稳定后接入，失败不影响既有绑定。接口落地后再更新全局架构和模块接口的实现记录。
