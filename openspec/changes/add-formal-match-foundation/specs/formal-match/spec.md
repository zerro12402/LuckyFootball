# Spec Delta

## Purpose

定义正式 6V6 比赛的阵容、场景装配、固定步计时和唯一终场结果，为观赛与下注提供稳定的只读输出。该能力可用预设动作验证，并为后续双方全 AI 决策提供统一比赛入口。

## ADDED Requirements

### Requirement: 正式比赛阵容与入口
系统 SHALL 只在双方各有六名合法上场球员且每队恰有一名门将时启动正式比赛；球员 ID MUST 唯一，球队和阵容引用有效，失败时不得留下部分运行的比赛。

#### Scenario: 双方阵容有效
- **WHEN** 正式入口收到两队合法阵容及有效场地、比赛配置
- **THEN** 系统装配十二名球员、一颗足球、球场和比分，并提供比赛推进入口

#### Scenario: 阵容无效
- **WHEN** 人数错误、球员 ID 重复、引用失效或缺少合法门将
- **THEN** 系统拒绝启动并给出明确失败原因

### Requirement: 正式入口隔离开发测试
正式比赛入口 MUST 不引用开发测试场景或接收键盘操控球员的命令；测试与未来 AI SHALL 经同一动作契约进入规则层。

#### Scenario: 正式模式加载
- **WHEN** 用户选择正式比赛模式
- **THEN** 系统只装配正式比赛资源与获准动作来源，开发测试预设和键盘球员适配器不被启动

### Requirement: 已有足球闭环在正式比赛中有效
正式比赛 SHALL 使用同一套移动、控球、传射、球路、进球、出界、击倒和扑救规则；任何时刻最多只有一名球员持球。

#### Scenario: 预设动作触发射门与重置
- **WHEN** 测试动作源提交合法射门并造成进球
- **THEN** 系统一次性释放球权、只计一次得分，并按既有球网运动和重置阶段继续比赛

### Requirement: 固定步计时与唯一终场
比赛 SHALL 使用可配置时长和模拟时间计时；达到时长后 MUST 产生一次正式终场结果、冻结比分并停止接受场上动作。暂停不得推进比赛时间，进球重置不得改用系统时钟。

#### Scenario: 比赛到达终场
- **WHEN** 已用模拟时间达到配置时长
- **THEN** 比赛进入终场并给出主胜、平局或客胜的唯一正式结果

#### Scenario: 暂停与重置边界
- **WHEN** 比赛暂停或正在进球重置阶段
- **THEN** 时间按已登记的阶段规则推进，恢复或重置不能重复触发终场

### Requirement: 比赛输出只读且可复现
系统 SHALL 公开比赛标识、种子、固定步、阶段、回合阶段、已用/剩余时间、比分和终场结果的只读快照及事件；读取 MUST 不修改状态或消耗随机数。

#### Scenario: 观赛服务重复读取
- **WHEN** 外部服务多次读取同一固定步的快照
- **THEN** 比赛和随机序列保持不变，外部不能通过快照回写球员、比分或球权

#### Scenario: 相同动作重放
- **WHEN** 两场比赛拥有相同阵容、初态、配置、动作序列和比赛种子
- **THEN** 状态、比分和事件序列相同
