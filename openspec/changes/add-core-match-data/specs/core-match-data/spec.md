# Spec Delta

## Purpose

定义幸运足球最小踢球流程使用的球员、足球、球场与配置数据契约，统一静态定义和比赛运行时状态的边界，使后续移动、带球、射门与边界规则可通过确定输入进行独立验证。

## ADDED Requirements

### Requirement: 统一表格静态数据
系统 SHALL 从统一表格读取球员、球场和比赛配置，并按稳定 ID 查询。球员定义 SHALL 包含速度、射门、强壮度、技巧、体力、抢断、守门七项 1–100 整数属性，以及 3–5 个不重复词条 ID。

#### Scenario: 读取合法球员
- **WHEN** 加载字段完整、数值合法且 ID 唯一的球员表
- **THEN** 返回可按 ID 查询的强类型定义，保留七项属性和词条 ID

#### Scenario: 无效球员数据
- **WHEN** 球员属性超出 1–100、ID 重复或词条数量不合法
- **THEN** 加载失败并提供错误原因，不发布不完整的球员集合

### Requirement: 数据集合原子加载
系统 MUST 在所需表格全部校验成功后发布完整索引；任一必需表格缺失或校验失败时 MUST 清空当前集合并报告错误。

#### Scenario: 比赛配置表加载失败
- **WHEN** 球员表与球场表合法但比赛配置表无效
- **THEN** 本次加载失败，三个集合均不保留可查询的部分结果

### Requirement: 静态定义与比赛状态隔离
系统 SHALL 将静态定义与位置、朝向、动作、球权等运行时状态分离。读取词条集合 MUST 返回副本；同一模拟 MUST 拒绝重复球员 ID 和第二个足球。

#### Scenario: 修改读取到的词条列表
- **WHEN** 调用者修改从球员定义读取的词条集合
- **THEN** 原静态定义保持不变

#### Scenario: 唯一运行时对象
- **WHEN** 同一比赛重复注册球员 ID 或再次注册足球
- **THEN** 注册失败并保留原对象及状态

### Requirement: 统一米制坐标
系统 SHALL 使用米表示逻辑位置、米每秒表示平面速度，以球场中心为原点，X 向右、Y 向下。显示换算 MUST 与逻辑状态隔离。

#### Scenario: 坐标往返
- **WHEN** 将一个米制位置按正像素比例转换为显示位置后再逆转换
- **THEN** 恢复原逻辑位置且转换过程不修改比赛状态
