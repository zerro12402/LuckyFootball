# Spec Delta

## Purpose

定义球员词条的表格化定义、合法分配和对 AI 行为权重的影响，使每名球员形成可解释且可复现的行为差异。正式版配置与 Demo 本轮覆盖互相隔离，词条不绕过动作资格或直接提交比赛结果。

## ADDED Requirements

### Requirement: 表格定义与球员词条引用有效
系统 SHALL 从集中表格加载只读词条定义，并校验稳定唯一 ID、合法条件与行为权重参数。每名正式球员 MUST 配置 3–5 个合法不重复词条，未知引用或非法配置必须导致加载失败。

#### Scenario: 合法定义和分配
- **WHEN** 词条表与球员配置均合法
- **THEN** 每名球员可按稳定 ID 取得对应定义，调用者不能修改仓库中的词条数据

#### Scenario: 词条不合法
- **WHEN** 存在未知词条、重复分配、数量越界或非法条件/权重
- **THEN** 系统给出失败原因并拒绝发布部分有效配置

### Requirement: 词条通过行为权重自然组合
系统 SHALL 在条件成立时把词条效果应用于 AI 的合法候选行为权重；多个词条通过统一组合规则产生效果，MUST 不建立显式 Combo 或另行生成比赛结果。

#### Scenario: 相同局面不同词条
- **WHEN** 两名球员面对相同合法候选但拥有不同词条
- **THEN** 条件匹配的行为权重产生可观察差异，来源可查询且结果可复现

#### Scenario: 改变遍历顺序
- **WHEN** 相同词条集合以不同顺序输入
- **THEN** 组合后的权重及同种子决策结果一致

### Requirement: 词条不覆盖比赛规则
词条 MUST 不直接改写七项基础属性、球权、比分或击倒/扑救结果，也不得恢复被状态或球权条件禁止的动作。

#### Scenario: 高射门倾向但动作非法
- **WHEN** 倒地或无球球员拥有提高射门倾向的词条
- **THEN** 射门仍不合法，词条不生成射门足球或状态副作用

### Requirement: 正式与 Demo 词条来源隔离
正式模式 SHALL 使用球员表中的词条 ID；Demo SHALL 可在创建比赛时注入合法的只读覆盖集合，不回写球员表且不在比赛中重新抽取。

#### Scenario: Demo 覆盖
- **WHEN** Demo 挑战向比赛传入合法的本轮词条
- **THEN** 比赛使用该覆盖，正式球员定义和原有静态词条保持不变

#### Scenario: 正式模式加载
- **WHEN** 系统加载正式配置而未请求 Demo 覆盖
- **THEN** 词条取自球员表，先前 Demo 数据不会泄漏到该场比赛
