# Design

## Notion 设计依据

- 球员数据与词条基础：[球员属性](https://app.notion.com/p/3e4f67bb9cfa8030be6bff06ef2a0ccc)、[资源规范](https://app.notion.com/p/3e1f67bb9cfa811bbe09e84d31665668)
- 行为依据：[球员基本行为2 — 多人交互行为](https://app.notion.com/p/3edf67bb9cfa809c8064c0049e0b4f1e)

这些是现有数据与行为依据，不代替尚待补齐的词条专题策划及程序设计。开始该模块实现前，须在 [设计文档](https://app.notion.com/p/3e4f67bb9cfa80248154cb4f8936ee72) 与 [程序架构](https://app.notion.com/p/3e6f67bb9cfa819ba789f46ac01e629d) 下补齐对应专题页。

## Context

参见 [proposal.md](proposal.md)。players.csv 和 PlayerDefinition 已支持 3–5 个词条 ID 以及数量/重复校验，但 DataRepository 尚未加载词条定义，AI 行为也尚未消费其效果。add-player-ai 提供中性权重扩展点；五场挑战提案已有总种子及随机词条生成计划。

## Goals / Non-Goals

**Goals:** 数据、分配与权重修正分别可测；支持正式静态词条和只读 Demo 覆盖；验证词条确实影响选择。

**Non-Goals:** 创建显式 Combo、永久改变基础属性、直接修改对抗结果；Demo 随机生成与五场持久化仍由挑战服务负责。

## Decisions

1. **词条表由本特性维护。** traits.csv 提供稳定 ID、合法角色/行为条件和权重参数，读取成只读强类型定义；事务式校验表格、球员引用、数量和重复。球队仓库归正式基础，挑战只引用词条仓库。
2. **使用有限条件与行为标识。** 采用可校验的条件/行为枚举与配置参数，不在表格中执行任意脚本。球员状态先影响合法性，再在合法候选中匹配词条。
3. **组合可解释且稳定。** 用固定规则组合匹配的权重修正，按稳定 ID 记录来源并限制到合法权重范围；中性修正为恒等。相同词条集合不因列顺序不同改变结果；全部候选权重为零时使用基础 AI 的合法回退，不恢复非法动作。具体数值写配置，测试自然组合而非组合名称分支。
4. **来源显式区分。** 正式模式绑定 PlayerDefinition.trait_ids；Demo 创建比赛时显式注入合法覆盖并复制为本场只读输入。覆盖不回写 CSV、不在比赛步中抽取，重置也不重新生成。挑战服务拥有跨五场固定集合和随机派生。
5. **验证效果不改变规则。** 相同局面下检查指定行为权重与决策序列变化，同时断言基础属性、动作资格、比分和球权不能被词条直接修改；常规有效属性与 F08 仍由属性/判定特性负责。
6. **文档与入口。** Notion 词条专题策划与《程序架构》下程序设计子页先就绪；对照用例进入既有共用测试模式，不新增单项场景。

## Risks / Trade-offs

- **现有词条 ID 没有定义** → traits.csv 覆盖现有合法 ID 并执行跨表校验，不静默忽略未知词条。
- **权重极端或叠加顺序不稳定** → 校验数值、稳定组合、来源记录及零权重回退测试。
- **Demo 覆盖污染正式配置** → 显式模式和只读绑定，测试回到正式模式及多场使用的隔离。

## Migration Plan

完成 Notion 功能文档 → 加载定义与校验分配 → 实现修正计算和覆盖接口 → 接入基础 AI → 固定输入/种子及正式比赛验收。挑战后续使用这些接口生成与保存词条；可单独回退效果接入至中性权重，不回写静态球员表。
