# Design

## Context

参见 [proposal.md](proposal.md)。PlayerDefinition 已保存七项属性；PlayerRuntime 当前只显式提供射门、强壮度和技巧，移动速度仍由注册参数传入，体力和全量属性修正尚未完成。前置 `complete-ai-match-demo` 以显式数值验证动作、空中球路、击倒与扑救，本特性把真实球员数据接入这些规则。

## Goals / Non-Goals

**Goals:** 从球员表到运行态、有效值、对抗结果形成单向可测链路；集中公式参数；在没有正式场景或完整 AI 时验证。

**Non-Goals:** 重写既有动作状态机、装配 6V6 场景、制作 AI/词条效果或更改已确认足球击倒临时规则。

## Decisions

1. **静态定义与动态体力分开。** 创建运行态时绑定只读 PlayerDefinition，当前体力独立维护；测试可显式注入数据，但正式注册禁止以 0 或缺省值掩盖缺失属性。相比把疲劳直接扣在基础属性上，此方案不会污染赔率输入或静态仓库。
2. **集中有效值与判定入口。** 无节点依赖的有效值计算器与判定器接收强类型上下文、CSV 配置和显式随机源；各动作只处理资格和结果提交。各保留的属性判定沿用 Notion《对抗判定公式》的映射，S形参数集中配置；追逐通过速度推进而不逐帧抽样。F03取消属性对抗，合法范围接触由既有接球流程100%取得球权，不抽样、不新增F03判定器。避免在各动作里重复实现同一差值函数。
3. **先资格，再抽样。** 距离、朝向、高度、动作状态与接触顺序仍由既有规则检查；需要属性对抗的判定在合法接触后比较属性；F03不比较属性或抽样。F08 严格比较锁定射门基础值与目标基础强壮度，跳过体力与通用概率，击倒后的球路抽样仍独立。
4. **分动作接线并做对照。** 依次接入移动/追逐、控球抢断、近身命中/击倒、足球闪避及扑救。对照测试固定几何、命令和随机输入，只改变一项属性，检查对应输入或结果；不要求每个概率事件都随属性变化必然翻转。
5. **文档与开发入口。** 编码前在《球员属性》《对抗判定公式》《球员基本行为2》补齐策划，并在《程序架构》下建立本功能程序设计子页。测试继续使用共用 GameModes / GameBootstrap，默认不做截图、录屏或离屏渲染。

## Risks / Trade-offs

- **旧测试依赖固定值/0 属性** → 保留显式测试夹具与正式校验的边界，迁移受影响测试，避免静默注入正式默认值。
- **体力被多个动作重复修正** → 每次判定只通过统一入口求有效值，记录修正来源，F08 单独断言。
- **传球接球与边界冲突** → F03不新增概率接线；沿用既有接球资格及接触排序，保留高度、球速、先越线及同一步多候选的唯一球权约束。

## Migration Plan

前置动作规则就绪 → 完成功能文档 → 绑定属性与体力 → 分动作接入公式 → 共用测试模式属性对照与无场景回归。正式比赛和 AI 在该特性验收后接入；实现出错可回退新绑定/判定接线，不修改球员静态表或前置动作语义。

## 本轮增量：仅 F01

按照用户逐条实现公式的顺序，先实现现有移动模块的速度接线，不以完成 F01 代表七项属性、体力或其他判定已实现。F01 程序设计已先建立在 Notion《程序架构》下。

- 基础跑速 = `player_speed_at_100_mps * speed / 100`；基准初值5.0m/s，CSV集中配置。75与100的实际跑速之比为3:4，不带最小速度截距。
- 当前投放表 speed 为75～100；通用属性校验/边界夹具仍为1～100，不在运行时钳制基础值。两条低速投放样本调整为75。
- `MatchSimulation.register_player_from_definition()` 从强类型定义读取 speed，通过 `PlayerRuntime.calculate_movement_speed_mps()` 计算实际米制速度，再沿既有注册链路写入状态机。`PlayerRuntime.speed_attribute` 只读保存输入值；原显式米制注册入口保留用于独立动作测试。
- GameBootstrap 的实际CSV球员全部走定义入口。旧对抗预设的射门/强壮度覆盖仍显式保留，不受 F01 改变。
- 无球与持球移动、MOVE命令驱动的AI追逐共用状态机；原持球0.9修正保持，突进和受击位移不重复乘速度属性。体力修正仍待1.3。

## F02 增量：概率抢断、失败起跳与双方 AI

- 现阶段使用基础 `tackling` 与 `technique`，概率为 `clamp(1/(1+exp(-(tackling-technique)/scale)), min, max)`；配置初值18、0.1、0.9，体力/站位修正保留待办。
- `TackleContestResolver` 接收合法接触之后的显式输入与样本函数，输出只读 `TackleContestResult`。每次抢断在ACTIVE窗口内首次合法接触才消耗一个样本；暂未接触则保留候选至窗口结束，成功或失败后都删除，避免逐帧重抽。
- `MatchSimulation` 新增可选 `tackle_sampler`，默认比赛种子源；`MatchEvent.tackle_contest` 记录属性、概率、样本。失败产生 `TACKLE_FAILED`，保留球权并尝试现有带球起跳，使用第7行动画和原起跳高度/时长，不打断其他动作锁或重复启动跳跃。
- CSV定义入口读取基础抢断，显式夹具默认50且可自行指定；与基础技巧一起只读保存，比赛不回写静态定义。
- `GameLoop` 可从同一固定步快照收集多个 `TackleChaseAI` 命令。共用抢断测试双方各一个实例，有球进攻、无球追抢、自由球追球；输入只保留重置/刻度，面板显示本次成功率与结果。完整6V6 AI仍不在本轮。
- 策划和程序设计已先写入 Notion；默认验证仅使用概率/状态/事件与无画面共用模式测试。

### F02 起铲提前量调整

将发起动作的 `tackle_start_range_m=1.8m` 与实际接触 `tackle_range_m=1.2m` 分开。AI用目标当前移动输入、实际跑速/持球倍率与自身抢断突进速度，预测前摇内相对接近量；阈值为 `min(start_range, max(0, contact_range + closing_speed * windup))`。迎面时提前，静止目标与背后追赶不盲目远距离起铲。真实F02抽样仍只发生在ACTIVE窗口内的1.2m接触，动作时长与成功率均不变。6项相关非表现回归测试通过。

## F03 决策：取消属性概率判定

用户确认不实现F03属性模块。传球进入符合现有普通接球资格的球员合法范围后100%被接住并取得唯一球权，不比较传球者技巧与拦截者抢断，不套体力/站位概率修正、不抽随机数。距离、高度、动作、可控球速、释放保护和边界资格继续由既有普通接球规则处理；不满足资格不属于随机拦截失败。多人仍按首次合法接触和稳定顺序决胜，指定接球目标不独占球权。旧的F03概率失败/高速成功偏转分支不再开发；射门和解围不属于此规则。技巧影响传球质量的需求也已取消，传球方向、落点和球路沿用现有固定规则，不再安排属性接线或准确度对照测试。本次只修订文档，不改运行代码，不标记新实现完成。
