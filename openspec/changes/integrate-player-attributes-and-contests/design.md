# Design

## Context

参见 [proposal.md](proposal.md)。PlayerDefinition 已保存七项属性；PlayerRuntime 当前只显式提供射门、强壮度和技巧，移动速度仍由注册参数传入，体力和全量属性修正尚未完成。前置 `complete-ai-match-demo` 以显式数值验证动作、空中球路、击倒与扑救，本特性把真实球员数据接入这些规则。

## Goals / Non-Goals

**Goals:** 从球员表到运行态、有效值、对抗结果形成单向可测链路；集中公式参数；在没有正式场景或完整 AI 时验证；先完成F11射偏选靶，再接入F04属性扑救。

**Non-Goals:** 重写既有动作状态机、装配 6V6 场景、制作 AI/词条效果或更改已确认足球击倒临时规则。

## Decisions

1. **静态定义与动态体力分开。** 创建运行态时绑定只读 PlayerDefinition，当前体力独立维护；测试可显式注入数据，但正式注册禁止以 0 或缺省值掩盖缺失属性。相比把疲劳直接扣在基础属性上，此方案不会污染赔率输入或静态仓库。
2. **集中有效值与判定入口。** 无节点依赖的有效值计算器与判定器接收强类型上下文、CSV 配置和显式随机源；各动作只处理资格和结果提交。各保留的属性判定沿用 Notion《对抗判定公式》的映射，S形参数集中配置；追逐通过速度推进而不逐帧抽样。F03取消属性对抗，合法范围接触由既有接球流程100%取得球权，不抽样、不新增F03判定器。避免在各动作里重复实现同一差值函数。
3. **先资格，再抽样。** 距离、朝向、高度、动作状态与接触顺序仍由既有规则检查；需要属性对抗的判定在合法接触后比较属性；F03不比较属性或抽样。F08 严格比较锁定射门基础值与目标基础强壮度，跳过体力与通用概率，击倒后的球路抽样仍独立。
4. **分动作接线并做对照。** 接入移动/追逐、控球抢断、近身命中/击倒、足球闪避；F11射偏可独立于近身接线实施，但必须在F04属性扑救前完成并验收。对照测试固定几何、命令和随机输入，只改变一项属性，检查对应输入或结果；不要求每个概率事件都随属性变化必然翻转。
5. **文档与开发入口。** 编码前在《球员属性》《对抗判定公式》《球员基本行为2》补齐策划，并在《程序架构》下建立本功能程序设计子页。测试继续使用共用 GameModes / GameBootstrap，默认不做截图、录屏或离屏渲染。

## Risks / Trade-offs

- **F05闪避与F06强者必胜混淆** → F06只在F05命中后执行，强壮差达到20不绕过闪避；等强或达阈值不消耗F06样本。
- **平局先提交一方造成另一方遗漏或重复掉球** → 锁定接触时双方状态/方向及球位置，验证完成后原子提交双人击飞，掉球至多一次。

- **旧测试依赖固定值/0 属性** → 保留显式测试夹具与正式校验的边界，迁移受影响测试，避免静默注入正式默认值。
- **体力被多个动作重复修正** → 每次判定只通过统一入口求有效值，记录修正来源，F08 单独断言。
- **传球接球与边界冲突** → F03不新增概率接线；沿用既有接球资格及接触排序，保留高度、球速、先越线及同一步多候选的唯一球权约束。

## Migration Plan

前置动作规则就绪 → 完成功能文档 → 绑定属性与体力 → 分动作接入公式 → 共用测试模式属性对照与无场景回归。正式比赛和 AI 在该特性验收后接入；实现出错可回退新绑定/判定接线，不修改球员静态表或前置动作语义。

## 本轮增量：仅 F01

按照用户逐条实现公式的顺序，先实现现有移动模块的速度接线，不以完成 F01 代表七项属性、体力或其他判定已实现。F01 程序设计已先建立在 Notion《程序架构》下。

- 基础跑速 = `player_speed_at_100_mps * speed / 100`；基准初值5.0m/s，CSV集中配置。75与100的实际跑速之比为3:4，不带最小速度截距。
- 当前投放表 speed 为75～100；通用属性校验/边界夹具仍为1～100，不在运行时钳制基础值。两条低速投放样本调整为75。
- `MatchSimulation.register_player_from_definition()` 从强类型定义读取 speed，通过 `PlayerRuntime.calculate_movement_speed_mps()` 计算实际米制速度，再沿既有注册链路写入状态机。`PlayerRuntime.speed_attribute` 只读保存输入值；原显式米制注册入口保留用于独立动作测试。
- GameBootstrap 的实际CSV球员全部走定义入口。旧对抗预设的射门/强壮度覆盖仍显式保留，不受 F01 改变。
- 无球与持球移动、MOVE命令驱动的AI追逐共用状态机；原持球0.9修正保持，突进和受击位移不重复乘速度属性。体力修正仍待1.3。

## F02 增量：概率抢断、失败起跳与双方 AI

- 现阶段使用基础 `tackling` 与 `technique`，概率为 `clamp(1/(1+exp(-(tackling-technique)/scale)), min, max)`；配置初值18、0.1、0.9，体力/站位修正保留待办。
- `TackleContestResolver` 接收合法接触之后的显式输入与样本函数，输出只读 `TackleContestResult`。每次抢断在ACTIVE窗口内首次合法接触才消耗一个样本；暂未接触则保留候选至窗口结束，成功或失败后都删除，避免逐帧重抽。
- `MatchSimulation` 新增可选 `tackle_sampler`，默认比赛种子源；`MatchEvent.tackle_contest` 记录属性、概率、样本。失败产生 `TACKLE_FAILED`，保留球权并尝试现有带球起跳，使用第7行动画和原起跳高度/时长，不打断其他动作锁或重复启动跳跃。
- CSV定义入口读取基础抢断，显式夹具默认50且可自行指定；与基础技巧一起只读保存，比赛不回写静态定义。
- `GameLoop` 可从同一固定步快照收集多个 `TackleChaseAI` 命令。共用抢断测试双方各一个实例，有球进攻、无球追抢、自由球追球；输入只保留重置/刻度，面板显示本次成功率与结果。完整6V6 AI仍不在本轮。
- 策划和程序设计已先写入 Notion；默认验证仅使用概率/状态/事件与无画面共用模式测试。

### F02 起铲提前量调整

将发起动作的 `tackle_start_range_m=1.8m` 与实际接触 `tackle_range_m=1.2m` 分开。AI用目标当前移动输入、实际跑速/持球倍率与自身抢断突进速度，预测前摇内相对接近量；阈值为 `min(start_range, max(0, contact_range + closing_speed * windup))`。迎面时提前，静止目标与背后追赶不盲目远距离起铲。真实F02抽样仍只发生在ACTIVE窗口内的1.2m接触，动作时长与成功率均不变。6项相关非表现回归测试通过。

## F03 决策：取消属性概率判定

用户确认不实现F03属性模块。传球进入符合现有普通接球资格的球员合法范围后100%被接住并取得唯一球权，不比较传球者技巧与拦截者抢断，不套体力/站位概率修正、不抽随机数。距离、高度、动作、可控球速、释放保护和边界资格继续由既有普通接球规则处理；不满足资格不属于随机拦截失败。多人仍按首次合法接触和稳定顺序决胜，指定接球目标不独占球权。旧的F03概率失败/高速成功偏转分支不再开发；射门和解围不属于此规则。技巧影响传球质量的需求也已取消，传球方向、落点和球路沿用现有固定规则，不再安排属性接线或准确度对照测试。本次只修订文档，不改运行代码，不标记新实现完成。

## F05/F06：近身闪避与强者胜或平（已实现）

公式见Notion[对抗判定公式](https://app.notion.com/p/3fdf67bb9cfa8119904ce87c51051c13)，策划见[多人行为第4节](https://app.notion.com/p/3edf67bb9cfa809c8064c0049e0b4f1e)，专题程序设计已建于《程序架构》下：[F05／F06近身闪避与强壮对抗](https://app.notion.com/p/402f67bb9cfa81218aeaeb0abc9c31bb)。现有首次合法接触已接入MeleeContestResolver，正常默认走公式；固定MeleeOutcome仅保留显式开发覆盖，F07独立待办。

```text
A = 进攻者基础强壮，T = 目标基础技巧，B = 目标基础强壮
F05 p_dodge = clamp(1/(1+exp(-(T-A-attack_advantage)/scale)),min,max)
默认attack_advantage=20、scale=18、min=0.10、max=0.90
首次合法接触抽u5：u5<p_dodge闪避，否则命中

仅命中时进入F06，D=abs(A-B)，H=20
D=0：DRAW，不抽F06
D>=H：强者胜，不抽F06
0<D<H：独立抽u6，u6<D/H强者胜，否则DRAW
弱者胜率始终为0；u5等号命中，u6等号平局
```

F05同值技巧/强壮时约24.8%闪避，技巧高20时50%。F06差5/10/15/19时强者胜率25%/50%/75%/95%，等强必平、差大于等于20必胜，均以F05已命中为前提。使用基础值，不加未声明的体力或主动闪避修正；不新增闪避命令。F06不套S形、10%～90%限制或已放弃的三权重方案。

已在现有首次合法攻击接触入口接入纯数据判定器与只读结果；MatchSimulation验证几何、窗口、动作和目标资格后才抽样。F05结果一旦产生即消费该攻击意图，不能下一帧重试；未形成合法接触沿既有未命中流程，不能伪记为技巧闪避。正常默认走公式，旧固定结果注入仅保留为显式开发测试模式。

只读MeleeContestResult包括攻击序列/双方ID、A/T/B、F05概率/样本/命中事实、D/H/强者身份、F06是否抽样/样本/条件胜率，以及DODGED/ATTACKER_WIN/TARGET_WIN/DRAW。未发生F06时无该阶段结果或样本，不能把占位0当成实际抽样。无资格抽0次，F05闪避或命中后F06确定性分支抽1次，命中且差在(0,H)内抽2次；样本独立，读取不抽样。

接触方向e由攻击者指向目标，位置重合时用既有攻击方向稳定兜底。ATTACKER_WIN目标沿+e击飞倒地；TARGET_WIN攻击者沿-e击飞倒地；DRAW双方沿+e/-e同时击飞倒地。目标持球时，目标败或平均先在接触点掉球，目标胜保球；无球目标不生成球权，不改变既有可攻击目标资格。胜利不自动夺球。掉球、两方状态、位移与事件必须一次提交，防止前一方状态变化使后一方被跳过。复用现有击飞/浮空/倒地/恢复配置，不把近身击飞计入F04足球击飞累计。

已接入CSV字段：melee_dodge_attack_advantage=20.0（有限非负）、melee_dodge_probability_scale=18.0（有限正数）、melee_dodge_probability_min=0.10与max=0.90（有限且0≤min≤max≤1）、melee_strength_auto_win_gap=20（正整数）。F05优势与F06必胜阈值分别配置，不因同为20而绑定。

共用攻击/反弹测试模式扩展双方属性、F05/F06独立样本及三结果预设，显示阶段结果、不抽样原因、方向与球权；不新建模块独立场景。验证差0/1/5/10/15/19/20/21、交换强弱、两阶段阈值等号、弱者不胜、去重、零距离后备方向、双人原子位移/掉球、暂停/重置及重放。F01/F02/F04/F11既有完成状态保持，F07独立待办；已实现代码及实际跨模块接口已摘要同步Notion《模块接口》。

## F11 增量：射偏与门柱外选靶（F04 前置，已实现）

### 设计依据与范围

以 Notion [对抗判定公式](https://app.notion.com/p/3fdf67bb9cfa8119904ce87c51051c13) 的 F11 为数值登记处，策划见 [球员基本行为2](https://app.notion.com/p/3edf67bb9cfa809c8064c0049e0b4f1e)，程序专题见 [门将扑救与射门三点](https://app.notion.com/p/401f67bb9cfa81339425fe33588786b3)。本节已完成2.3a～2.3c并独立验收；F04属性公式已在后续2.4及2.4a～2.4c实现并验收。

普通射门、空中射门、头球攻门形成SHOT时共用；传球、解围不适用。实际合法离脚/头球触球时锁定射手的射门基础值 S∈[1,100]。F11不乘体力、距离、角度、压力或门将属性，不套通用S形概率；不改变射门属性对初速度的既有影响。

### 公式与目标

```text
p_miss = p1 - (p1 - p100) * (S - 1) / 99
默认 p1=0.45，p100=0.05
即 p_miss = 0.45 - 0.40 * (S - 1) / 99

u_miss ∈ [0,1)
u_miss < p_miss：射偏
u_miss >= p_miss：原有上中下三点选靶

射偏：d=-1或+1，各50%；m=Uniform(0.2,1.0)m
aim_x = goal_x
aim_y = goal_y + d * (goal_width_m/2 + ball_radius_m + m)
```

S=1/25/50/75/100时，默认射偏率约45%/35.3%/25.2%/15.1%/5%。d是同一进攻球门两根门柱的场地平面Y两侧，不是更换进攻球门或改变离地高度。射偏目标不得再钳制到门柱内；未射偏才沿用原1:1:1三点。

### 接入边界与结果表达

- 在现有实际释放选靶入口接入纯数据计算/判定，普通和空中射门的离脚路径与头球接触路径共用，不由输入适配器、AI或表现层计算。
- 拟扩展只读选靶上下文以区分门内目标/射偏目标，记录锁定S、概率、样本、门柱侧、偏移、目标点和射门序列；不能把射偏侧伪装成现有扑救UPPER/LOWER通道。具体类型和字段在实现时确定，不提前登记为现有接口。
- 原有球速、力度、释放高度、减速及高度演化算法保留；目标变化只重算方向和既有目标距离相关的高度终点，不额外保证球飞到门外。
- 射偏只是选靶结果，足球仍可撞人、被合法接住、反弹或提前停止；不立即发出出界/进球事件，不凭射偏标签强制跳过F04。门将实际合法接触才独立结算，边界按真实连续球路与最早事件裁定。
- 本次不更改F04临时50%成功或F08规则；F11验收后再开展现有2.4的F04属性工作。不得用射偏率冒充扑救成功率，未射偏也不等于进球。

### 随机时序和测试注入

实际合法释放 → 抽一次F11 → 射偏则各抽一次d和m，未射偏则抽一次三点通道 → 锁定目标 → 真实飞行与接触。

射偏分支目标抽样共3次，不抽三点；未射偏分支共2次，不抽d/m。各抽样用途独立，不复用同一个样本；后续实际接触的F04/F07/F08抽样另计。无效动作、触球前取消、读取快照、展示不抽样；一次实际释放只判一次，飞行中属性变化不回改结果。

独立注入射偏样本、侧、偏移和三点通道；固定通道不隐式跳过F11。显式强制分支的测试不消耗对应生产样本，既有只测试扑救的预设需明确强制未射偏，以隔离F04。面板同时显示选靶与扑救两个结果，不能混为“射门失败”。新增抽样后基于新序列验证同种子重放，不沿用旧种子恰好抽到的结果。

### F11 实现记录

ShotAccuracyResolver负责纯数据概率与目标计算；MatchSimulation只在实际释放时按分支调用独立样本。ShotAim新增只读is_miss、shooting、miss_probability、miss_sample、post_side、miss_margin_m；普通/空中BALL_SHOT、头球射门BALL_HEADED及足球快照保留选靶事实。MatchSimulation构造尾部追加shot_miss_sampler、shot_miss_side_sampler、shot_miss_margin_sampler、shot_miss_override（-1随机、0未射偏、1射偏）；强制分支以sample=-1明确未抽样，不影响三点注入的独立性。

## F04 属性版：距离与击飞衰减（已实现）

以Notion《对抗判定公式》F04属性版为数值来源，《门将扑救与射门三点》为专题程序设计。保留F11已完成状态，2.4及2.4a～2.4c已完成，固定50%临时概率已替换；其他全量属性、体力和近身对抗任务不因本次完成而勾选。

```text
S0 = 实际释放锁定的基础射门
d  = 释放至门将实际接触的累计平面路径（米）
n  = 本次射门此前成功击飞的不同非门将防守人数
A = 1 / (1 + (max(d-free_distance,0)/distance_scale)^2)
B = knockdown_retention^n
S_effective = S0 * A * B
G = 门将基础守门
p_shot_wins = clamp(1/(1+exp(-(S_effective-G)/probability_scale)), win_min, win_max)
p_save = 1 - p_shot_wins
等价直接写法：p_save = clamp(1/(1+exp(-(G-S_effective)/probability_scale)), 1-win_max, 1-win_min)
默认参数：p_save = clamp(1/(1+exp(-(G-S_effective)/18)), 0.10, 0.90)
合法门将接触时抽一次u；u<p_save为CATCH，否则MISS
```

默认免衰减5m、距离尺度15m、每次击飞保留0.85、概率尺度5、射门胜出上下限0.10/0.90。d≤5时A=1，d=20时A=0.5。S0=80、G=70，d=15且n=0/1/2时，有效射门约55.4/47.1/40.0，射门胜出率均为10%（触及配置下限）。射门胜出仅表示门将未守住，真实越线才进球。

### 累计上下文与提交边界

- 定义属于同一射门序列的独立累计上下文：路径长度、已击飞防守者ID集合。BallShotSource保留原始只读S0；PlayerRuntime显式绑定PlayerDefinition.goalkeeping，当前F04使用基础守门G。只读结果已追加S0/G/d/n、倍率、有效射门、两项概率及样本。
- 按实际已提交运动段累计L，只计平面路程，接触步只累计到接触时刻，不能取整步末或射手到门将的当前直线距离。反弹、偏转、门将漏球继续同一次累计，暂停/静止/读取不增加距离。
- 现有flight_distance_m属于当前运动段的高度曲线，反弹的_launch_shot会清零；不能直接复用为整次射门累计，也不能为衰减改变高度公式。每段只累计一次，余步按重算后的新轨迹继续。
- F08成功击飞提交后加入目标ID；同一射门同一防守者至多计一次。未命中、闪避、未倒及门将中路失败击飞不计。以门将接触之前已提交事实为准，同刻沿既有稳定接触排序。
- 新的实际释放产生新序列、L=0和空集合；取得球权、重置或轨迹终止清理旧上下文。仅新建反弹运动段不算新射门。新射门重新锁定S0，不继承旧累计。
- S_effective是浮点判定值，允许低于1，不回写基础值，不再额外乘球速或未登记疲劳倍率。F11准确性和F08击倒继续读取原S0；本衰减只服务F04。F08按当前已实现规则S0≥B击倒、相等固定反弹、严格大于才抽继续/反弹，不能被本衰减意外改写。
